╔══════════════════════════════════════════════════════════════════════════════╗
║                        SCROLL STABILIZATION TIMELINE                          ║
╚══════════════════════════════════════════════════════════════════════════════╝

    User Scrolls Down ↓
         │
    0ms  ├── Scroll event → Cancel timer, start 500ms timer
         │   Queue remains unchanged, workers continue
   50ms  ├── Scroll event → Cancel timer, start 500ms timer
         │   Queue remains unchanged
  100ms  ├── Scroll event → Cancel timer, start 500ms timer
         │   Queue remains unchanged
  150ms  ├── Scroll event → Cancel timer, start 500ms timer
         │   Still scrolling...
  200ms  ├── User stops scrolling
         │   500ms timer counting down...
  300ms  │   (no scroll, timer active)
  400ms  │   (no scroll, timer active)
  500ms  │   (no scroll, timer active)
  600ms  │   (no scroll, timer active)
  700ms  └── TIMER FIRES! ← Scroll stable for 500ms
              │
              ├─ Calculate visible images
              ├─ Clear priority queue
              ├─ Rebuild queue with new priorities
              └─ Workers start processing visible images

  │   TOTAL: ~5-50 KB                        │

╔══════════════════════════════════════════════════════════════════════════════╗
║                           KEY DESIGN DECISIONS                                ║
╚══════════════════════════════════════════════════════════════════════════════╝

  1. Fl::awake for thread safety
     └─ FLTK requires all widget operations on main thread
     └─ Workers use callback → Fl::awake → main thread update
     └─ Prevents race conditions and crashes

  2. 500ms scroll stabilization
     └─ Prevents queue thrashing during rapid scrolling
     └─ Balances responsiveness with efficiency
     └─ User doesn't notice delay (expects smooth scroll)

  3. Progressive quality levels
     └─ Show something quickly (TINY: 32px)
     └─ Improve incrementally (64→128→256→512→1024)
     └─ Stop when no longer visible or at maximum

  4. Priority queue
     └─ Visible images processed first
     └─ Ensures best user experience
     └─ Background images load opportunistically

  5. JPEG DCT-domain scaling
     └─ Faster than full decode + resize
     └─ Lower memory usage
     └─ Leverages libjpeg-turbo optimization

  6. Grey placeholders
     └─ Immediate visual feedback
     └─ Shows layout and dimensions
     └─ Better than blank space or loading spinner

  7. Minimal dynamic allocation
     └─ Widgets created once during layout
     └─ Only thumbnail data changes
     └─ Reduces memory fragmentation
